# v0.1.0

First release since v0.0.11 (March 2026). This is the release where massrelay
grows from a bare relay into an operable, observable, deployable service. It
adds the observability stack, the security and JWT auth middleware, a
token-gated admin API, and a full Docker + Caddy deployment path. It also
migrates the TypeScript client to canonical protobuf-es message types and
refreshes all panyam/* dependencies onto their latest lines. The dependency
refresh carries a breaking internal auth API change, so the version moves to
0.1.0 rather than another patch.

## Breaking

- **oneauth 0.0.x to 0.1.x migration** (`web/middleware/auth.go`). The oneauth
  `apiauth` and `keys` packages were reworked. If you embed the relay auth
  middleware or configure a KeyStore directly, update these call sites:
  - `apiauth.APIMiddleware.TokenQueryParam` becomes `LegacyQueryParamBearer`.
  - `apiauth.GetUserIDFromAPIContext(ctx)` becomes `GetSubjectFromAPIContext(ctx)`.
  - `keys.InMemoryKeyStore.RegisterKey(id, key, alg)` becomes the request/response
    form `PutKey(ctx, &keys.PutKeyRequest{Record: &keys.KeyRecord{ClientID: id, Key: key, Algorithm: alg}})`.
- **Go 1.26.4 is now the minimum** (raised from 1.26.1), required by oneauth v0.1.36.
- **TypeScript client wire types.** `CollabEvent` and related messages now use
  canonical protobuf-es `Message` types with `fromJson()`/`toJson()` at the
  boundary. TS consumers that reached into the old hand-rolled JSON shapes may
  need to adjust (issue 9).

## Added

- **OpenTelemetry metrics** (Prometheus `/metrics` and OTLP export), a local
  Grafana LGTM stack via docker-compose, and provisioned dashboards (PR 10).
- **Relay-side JWT auth middleware** built on oneauth: multi-tenant KeyStore
  lookup by `client_id`, custom relay claims, and a subject deny list
  (issue 12, PR 11).
- **Per-subject rate limiting** via `RELAY_PER_SUB_RATE` and `SubjectKeyFunc`,
  with rejections wired to OTEL metrics (issue 14, PR 11).
- **Token-gated admin API**: `/admin/status` and `/admin/rooms`, guarded by a
  bearer token with constant-time comparison.
- **Security middleware**: origin allowlist, CORS reusing the same origin
  checker, trusted-proxy IP extraction, panic recovery, and connection limits.
- **Structured logging** with slog to JSON stdout, keyed by `component` for Loki.
- **Deployment stack**: Dockerfile, production and dev docker-compose (Caddy +
  relay with auto TLS), host bootstrap and DNS scripts (`setup-host.sh`,
  `add-relay-dns.sh`), and pool management scripts.
- **PRM endpoint**: RFC 9728 `/.well-known/oauth-protected-resource` (PR 18).
- **`make audit`** target running govulncheck, gosec, and gitleaks.
- **`tsc --noEmit` in CI** plus stricter TypeScript types across the client (PR 18).

## Changed

- **Proto model refactor**: embed `PeerInfo` in `CollabClient`, move `Metadata`
  onto `PeerInfo`, and extract a shared `Room` proto message (PR 7, PR 8).
- **Graceful shutdown** now uses `servicekit` `ListenAndServeGraceful`, removing
  manual signal handling (issue 17).
- **Generic hardening middleware** (rate limit, origin, CORS, recovery, logging,
  connection limit, Guard) lifted into `servicekit/middleware`; relay-specific
  middleware stays in `web/middleware/`.
- **Dependency refresh**: oneauth v0.0.55 to v0.1.36, servicekit v0.0.12 to
  v0.1.3, gocurrent v0.0.13 to v0.1.1, goutils v0.1.8 to v0.1.13, and the
  TypeScript `@panyam/servicekit-client` ^0.0.6 to ^0.0.7.
