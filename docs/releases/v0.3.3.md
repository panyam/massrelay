# v0.3.3

Auth works in the relay binary now, and `CollabClient` reconnects on its own.
Until this release `NewRelayApp` never built a key store, so a relay started
with `RELAY_AUTH_REQUIRED=true` quietly accepted every connection, and a client
whose socket dropped just stayed dropped. Connections also end when their
token expires, where before they outlived it indefinitely. Two defaults change
behavior, so read the first section before upgrading: `RelayApp.Init` now
refuses to start open, and a slow-consumer eviction reconnects instead of
ending the session.

Two missions closed with this release, each with an exercise that runs against
the relay binary in CI: `make exercise-auth` (issue 53) and
`make exercise-reconnect` (issue 54).

## Changed (behavior)

- **The relay refuses to start open** (issue 56, PR 58). `RelayApp.Init`
  returns `ErrAuthRequiredNoKeys` when `RELAY_AUTH_REQUIRED=true` and no key
  source is set, and an error for an unreadable or malformed keys file or a
  JWKS URL it can't fetch at startup. The binary exits on any of these.
  - Migration: set `RELAY_AUTH_KEYS_FILE` or `RELAY_AUTH_JWKS_URL` alongside
    `RELAY_AUTH_REQUIRED=true`. An embedder that builds its own `Guard` and
    also sets `RELAY_AUTH_REQUIRED=true` needs a key source too.
- **A slow-consumer eviction reconnects** (issue 38, PR 59). Reconnect is on by
  default, so `onSessionEnded("slow_consumer")` no longer fires; the client
  rejoins the same session instead.
  - Migration: pass `reconnect: false` to get the old behavior.

## Added

- **Signing keys from config** (issue 56, PR 58). `RELAY_AUTH_KEYS_FILE` is a
  JSON array of `{client_id, alg, key}`, and `RELAY_AUTH_JWKS_URL` fetches
  public keys matched by `kid`. In `deploy/production`, keys go in
  `./secrets`, mounted read-only at `/etc/massrelay` (a directory, since docker
  turns a missing single-file mount into an empty directory).
- **`CollabClient` reconnects** (issues 38 and 57, PR 59). After the socket
  closes without `disconnect()`, or an eviction, it backs off, checks
  `GET /api/v1/rooms/{sessionId}`, and rejoins on a 200. A 404 ends with
  `onSessionEnded("session_gone")`, so a relay restart no longer leaves a
  phantom room, and running out of `maxRetries` ends with
  `"reconnect_failed"`. New options are `reconnect` (default true),
  `retryDelayMs`, `onReconnecting`, and `getToken` for a fresh JWT on every
  connection.
- **Connections end at the token's `exp`** (issue 60, PR 62). The peer leaves
  its room and gets `SessionEnded{token_expired}`. With `getToken` set,
  `CollabClient` reconnects on a fresh token; without it, it reports
  `onSessionEnded("token_expired")`.
- **`JoinRoom.must_exist`** (issue 61, PR 62). Joins only a room the relay
  already has, answering `ErrorEvent{ROOM_NOT_FOUND}` otherwise. `CollabClient`
  sets it on every rejoin, which closes the window where a room lost between
  the room check and the join came back empty.
- **`RelayApp.Close()`** (PR 62) stops the JWKS background refresh, and `main`
  calls it on shutdown.
- **Exercises and interop tests against the binary.** `make exercise-auth`
  (issue 55, PR 58) and `make exercise-reconnect` (issue 57, PR 59) run in CI.
  New interop tests cover slow-consumer eviction as the TS client sees it
  (issue 50, PR 52) and peer identity with keys from `RELAY_AUTH_KEYS_FILE`,
  including an addressed call and reply the way the mcpkit room bridge makes
  them (issue 27, PR 65).

## Changed

- `CollabEngine` reports `session_gone` and `reconnect_failed` with their own
  messages instead of "The owner ended the sharing session".
- servicekit v0.2.2 (was v0.2.0), and `@panyam/servicekit-client` ^0.2.2 in
  development. Neither release changed an API massrelay uses.

## Fixed

- `RelayClaims.ExpiresAt` and `IssuedAt` were always zero, because oneauth's
  custom claims leave out `exp` and `iat`. The middleware now reads them from
  the verified token (PR 62). Issue 63 tracks a oneauth accessor for this.
- `deploy/production/docker-compose.yml` passes `RELAY_AUTH_REQUIRED` and
  `RELAY_AUTH_ISSUER` to the relay container. Before, both were set in `.env`
  and never reached it.

## Known limits

- A token can't be refreshed inside a live session; the client reconnects with
  a new one instead (issue 13).
- `DenySub` doesn't end streams already open for that subject (issue 63).
