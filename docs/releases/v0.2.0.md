# v0.2.0

This release lets an app address one peer in a room and trust who that peer
is, which the mcpkit page-tool bridge and diffpp's ReviewRouter both need. It
also fixes a bug that made the relay binary from v0.1.0 and v0.1.1 refuse
every WebSocket connection, so anything deployed from those tags should be
upgraded. The version moves to 0.2.0 because the relay now refuses some
client behavior it used to accept (spoofed `client_id`, actions before the
join, a second join) and two unused JWT claims are gone.

## Fixed

- **The relay binary accepts WebSockets again** (PR 26). `main.go` wraps every
  route in servicekit's `RequestLogger`, whose status recorder didn't
  implement `http.Hijacker`, and gorilla/websocket refuses an upgrade without
  it. Every `/ws/` request in v0.1.0 and v0.1.1 failed with a 400 and the log
  line `websocket: response does not implement http.Hijacker`. Handler-level
  tests never saw it. Fixed upstream in servicekit v0.1.7 (servicekit PR 38),
  and guarded here by `TestRelayHandlerAcceptsWebSocket` and the new interop
  suite.
- **A connection can no longer act as another peer** (PR 24). The stream used
  to pass the client's `client_id` straight through, so a connection could
  send updates, or a `LeaveRoom` that removed someone, as any other peer. It
  now stamps the connection's own id and rejects any action before the join.
- **A second `JoinRoom` on one connection** gets `ErrorEvent{ALREADY_JOINED}`
  (PR 26). It used to create a second client that the stream forgot, which
  then stayed in its room as a ghost peer.

## Added

- **Addressed `AppMessage`** (issue 23, PR 24). `AppMessage.to_client_id`
  delivers to one peer in the sender's room, and answers the sender with
  `ErrorEvent{PEER_NOT_FOUND}` when that peer isn't there. Empty keeps the
  room-wide fan-out. Embedding servers get `CollabService.DeliverAppMessage`
  with `ErrPeerNotFound` / `ErrRoomNotFound`.
- **`PeerInfo.identity`** (`PeerIdentity{subject, client_id}`), filled from the
  connection's validated JWT. Clients can't set it, and an anonymous peer has
  none. In-process callers attach one with `services.WithPrincipal`.
- **`rooms` JWT claim**, a string or array of exact session ids or `prefix*`.
  A join outside it gets `ErrorEvent{ROOM_FORBIDDEN}`, and a restricted token
  must name its session.
- **TypeScript**: `sendAppMessage(kind, payload, { to })`, and `onAppMessage`
  receives the sender's `fromClientId` as a third argument.
- **Interop suite** (PR 26). `npm run test:interop` / `make test-interop`
  builds the relay binary and runs real TS clients against it, also as its own
  CI job.

## Changed

- servicekit v0.1.3 to v0.1.7. Besides the fix above, this brings v0.1.6's
  graceful shutdown change: request contexts are cancelled before the drain,
  so open WebSocket streams close at shutdown rather than holding the drain
  timeout.
- CI runs on Node 22.

## Removed

- The `max_rooms` and `max_msg_rate` claims (issue 25). They were parsed into
  `RelayClaims` and never enforced. Tokens that still carry them are accepted
  and the claims are ignored.

## Known gap

The relay binary still has no way to configure signing keys (the auth
`KeyStore` in `NewRelayApp` is nil), so token validation, `PeerInfo.identity`
and the `rooms` claim only work in servers that embed the relay and supply a
`KeyStore`. Tracked on issue 27.
